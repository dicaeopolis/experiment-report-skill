# 最终审阅

交付报告包之前使用此审阅流程。

## 教师侧可读性检查

- 以一位未见过用户工作笔记的课程教师的身份通读完整报告。
- 假设除广泛的领域常识和报告自身定义的内容外无隐藏上下文。
- 修订任何需要未陈述背景、缺失定义或先前对话上下文的章节、图形或表格。
- 删除假定可访问笔记本、日志、JSONL 文件或任何后台产物的措辞。
- 删除内部资产文件名和仅用于工作流的版本名，除非用户明确要求。
- 首先检查 `实验目的` 及类似的高层级章节。它们应直接描述实验任务和学习目标，而非报告写作策略或包组织评论。
- 删除后台标签，如 `当前实验包中的`、`对齐版`、`新版 notebook`、导出目录名、包文件夹名及类似的内部标识符。
- 删除面向教师的关于指南的可见提醒，如 `根据手册要求`、`按文档要求` 或类似的元措辞，除非用户明确要求该风格。
- 删除不属于实验内容本身的模糊组织口号，如 `面向课程文档的实验组织方式`。

## 防御式写作检查

按 [defensive-writing.md](defensive-writing.md) 逐类排查。以下每一条都以"删掉之后文章是否损失信息"为判据。

- **自证**：删除所有关于自身正确性的陈述，如 `我们另写了一份实现进行比对`、`我们设置了内部一致性校验`、`确认没有引入编码错误`、`最大差异为…`。验证自身代码的工作属于代码仓库。
- **预防性反驳**：删除为选择预先辩护的句子（`若…就会…`、`因此并非可忽略的调整`、`避免…信息进入训练过程`）。只保留取值与实际效果。
- **边界声明**：删除否定句式的沉默陈述（`未引入…`、`未采用…`、`未对…作要求`、`未单独测定…`、`适用范围有限`）。边界改用肯定句式讲事实。
- **反事实句**：删除用假设的替代做法证明当前选择正确的句子。例外：若那组数字确实测过，它是实测对比，保留。
- **位置检查**：分析是否被写进了 `实验结果` 节（结果节应陈述事实）？同一论点是否在结果节与分析节各写一遍？
- **结论检查**：结论节是否重述了正文的分析与数据？结论只总结所得与有边界的收获。
- **自造结构检查**：报告是否出现了讲义未要求的对照结构？是否把数据集、类别数、指标定义各不相同的两组结果并排比较，并归因于单一差异？

注意与"必要的严谨"区分，以下不要误删：指标口径与统计集合的说明、真实存在且测过的另一组配置的对比、影响结果的预处理细节、观察与推断的推理链。

## 句子指向检查

- 删除指向本报告自身而非实验的句子，例如 `为便于与下文表述对应`、`图注数字与正文一致`、`需要单独说明`、`这样安排是为了`、`这一点在结果解读时需要保留`。
- 用枚举清单无法穷尽这类句子，判据是**句子的指向对象**：它在谈论实验，还是在谈论本文？

## 术语与行文压缩检查

- 检查同一事物是否出现两种叫法（如前文"方向区间"、后文"方向分箱"）。全文统一。
- 删除需要读者反推的压缩表述，即使它更短：`逐维比对`、`方向分箱是否跨 bin 插值`、`早停耐心值`、`按行列切片`。改法是把作者脑内的缩写展开为完整说法。
- 判据是读者是否需要反推一次以上，不是字数。`按每个维度依次比对` 比 `逐维比对` 长，但更好读。
- 检查重复的修辞对比句式：`不……而……`、`若……则……`、`并非……而是……`。同一句式在全文出现多次即应改写，即使每次单独看都成立。

## 报告语言检查

- 删除读起来像是为写作者、编辑者或演示者所写的措辞。
- 删除元写作、元阅读和元演示语言。
- 避免标题或正文中出现：
  `下面我们来看`、`这一部分主要说明`、`本节先介绍`、`如上所述`、`接下来展示`、`本页`、`讲到这里`、`这样安排是为了`

## 证据与覆盖检查

- 确认每项重要结论由具体结果、图形、表格、实现事实或提供的笔记支持。
- 确认没有结果被编造、四舍五入为更强的声称或泛化到超出所供材料的范围。
- 当审阅一段被标记为推测性或超越证据的文字时，区分两种情况：
  1. **幻觉或不支持的主张**：文本断言了一个实验材料中不存在的事实、机制或结果。通过移除或用具体证据支撑来修复。
  2. **有推理的分析或洞见**：文本以数据为基础、用合理的因果机制解释了观察结果。不要将此标记为需删除的违规。取而代之地，验证推理链是否完整：观察应在解释之前陈述，推断步骤应可见。如果推理不清晰，扩展它而非删除它。
- 确认报告未悄悄跳过解读结果所必需的实验设置关键项。
- 如果包中包含教师下发的实验讲义或检查清单，确认可用材料覆盖了每个要求的实验阶段。如果不覆盖，停止并告知用户实验不完整，而非交出一份最终报告。

## 结构、术语与公式检查

- 确认报告遵循课程实验报告结构，除非用户提供了不同的模板。
- 如果用户提供了教师检查清单，确认报告遵循该清单而非通用默认结构。
- 在首次出现时解释新的技术术语。
- 在首次出现时或紧邻处定义每个新的数学符号。
- 确认公式、图形和表格都有足够的局部解释，能够在打分过程中被理解。

## 改稿顺序检查

审阅必须按 结构 → 段落 → 句子 → 格式 的顺序进行，不可颠倒。顺序错了，句子会越改越顺，而不该存在的整节内容始终留着。

- **结构层**：每一节为什么存在？若某节是在论证自己的设计选择正确、或只是重述别处内容，整节删除。
- **段落层**：每一段的落点是什么？同一论点是否在两处各写一遍？
- **句子层**：措辞、术语统一、压缩表述、修辞句式。
- **格式层**：图表尺寸、编号、引用配对。

## 篇幅检查

- 若讲义规定了页数或体积上限，核对是否满足。
- 篇幅不足时按信息密度从低到高删：自证与辩解 < 重复表述 < 一般性铺垫 < 具体方法与数据 < 图。**先删的永远不是图。**
- 检查是否出现"为压篇幅而删除图、同时保留大段重复文字"这种顺序颠倒的做法。若需调整图占用的空间，改尺寸而非删图。

## 编译与打包检查

- 确认包为 Overleaf 就绪或者已经编译成一份可用的 PDF 报告。
- 确认主入口文件、书目文件、图形和其他资源使用一致的相对路径。
- **无死资产**：扫描报告项目目录。每个非 TeX、非编译产物的文件必须通过文档源码中的某个引用可达——`\includegraphics`、`\input`、`\bibliography` 或任何其他引入命令。存在于项目中但源码从未引用的文件是死资产。
- 交付前删除占位文本、TODO 标记、空章节和未使用的资产。

## 语言清洗检查

- 当直接正面陈述更清晰时，删除低信息的对比措辞。
- 保留能传达真实实验差异、排序差异或参数效应的对比。
- 优先使用有边界的陈述，如"实验结果表明"或"在当前设置下观察到"，而非证据不能充分支持的更强声称。
- 删除面向评分者或写作者的元评论，如 `对于课程实验而言，这一点非常重要`。
- 必须使用散文而非报告正文中的项目符号列表，除非教师模板或用户明确要求列表。
- 尽量避免使用破折号。
- 保留自然的课程原生术语，如 `dropout`、`embedding` 和 `batch size`，当它们比强制翻译读起来更好时。
- 删除生硬的英文携带词，如当有更直接的中文短语（“做参数扫描”）时避免 `sweep` 等不自然的英文插入。
- 当来源是用户自己的本地环境或直接观察到的结果时，将模糊的直接观察措辞如 `结合本地运行环境信息，可以确认` 替换为直接的事实陈述。
- 删除通用的 `如果后续……` 或未来工作段落，除非教师模板或用户明确要求。
- 对于课程报告任务，不要过度强调局限性，除非教师明确要求。
